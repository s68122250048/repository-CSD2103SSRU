**อธิบายอัลกอริทึม**

**อัลกอริทึมที่ 1: Recursive Algorithm**
แนวคิดหลักของวิธีนี้ประกอบด้วย 2 ส่วนสำคัญ ได้แก่

* **Base Case (เงื่อนไขหยุด)**: ใช้หยุดการเรียกซ้ำ เมื่อสตริงเป็น null หรือมีความยาวไม่เกิน 1 ตัวอักษร
* **Recursive Step (ขั้นตอนเรียกซ้ำ)**: ทำงานโดยดึงตัวอักษรตัวสุดท้ายของสตริงปัจจุบัน แล้วนำไปต่อกับผลลัพธ์จากการเรียกเมธอดตัวเองอีกครั้ง โดยส่งสตริงที่ตัดตัวสุดท้ายออกไปประมวลผลต่อ

กล่าวโดยสรุป วิธีนี้จะค่อย ๆ แยกตัวอักษรจากท้ายสตริง แล้วนำมาประกอบใหม่ผ่านการเรียกซ้ำจนถึงเงื่อนไขหยุด

---

**อัลกอริทึมที่ 2: Iterative Algorithm**
แนวคิดของวิธีนี้คือใช้การวนลูปแทนการเรียกซ้ำ โดยเริ่มอ่านตัวอักษรจากตำแหน่งสุดท้ายของสตริงไปยังตำแหน่งแรก จากนั้นนำตัวอักษรแต่ละตัวมาต่อกันด้วย `StringBuilder` ซึ่งสามารถแก้ไขค่าได้โดยไม่ต้องสร้างอ็อบเจ็กต์ใหม่ทุกครั้ง จึงช่วยประหยัดหน่วยความจำและเพิ่มความเร็ว

---

**Pseudocode**

1. **Recursive Algorithm**

```
Algorithm reverseRecursive(s)
    If s is null OR length(s) <= 1 Then
        Return s
    End If
    lastChar = s[length(s) - 1]
    remaining = substring(s, 0, length(s) - 2)
    Return lastChar + reverseRecursive(remaining)
End Algorithm
```

2. **Iterative Algorithm**

```
Algorithm reverseIterative(s)
    If s is null Then
        Return null
    End If
    Create empty StringBuilder sb
    For i = length(s) - 1 down to 0
        Append s[i] to sb
    End For
    Return sb.toString()
End Algorithm
```

---

**ตัวอย่างการทำงาน**
Input: `"pots&pans"`
Output: `"snap&stop"`

---

**วิเคราะห์ Time Complexity**

* **Recursive Algorithm: O(n²)**
  เนื่องจากมีการเรียกซ้ำทั้งหมดประมาณ n ครั้ง และในแต่ละครั้งมีการใช้ `substring()` และการต่อสตริงด้วย `+` ซึ่งใช้เวลา O(n)
  จึงได้สมการ:
  T(n) = T(n-1) + O(n) → สรุปเป็น O(n²)

* **Iterative Algorithm: O(n)**
  ใช้ลูปเพียง n รอบ และในแต่ละรอบทำงานคงที่ (O(1)) เช่น `charAt()` และ `append()`
  รวมแล้วเป็น O(n)

---

**วิเคราะห์ Space Complexity**

* **Recursive Algorithm: O(n²)**
  มีการใช้ Call Stack ลึก n ระดับ และแต่ละระดับมีการสร้าง String ใหม่ ทำให้หน่วยความจำเพิ่มสะสม

* **Iterative Algorithm: O(n)**
  ใช้พื้นที่หลักจาก `StringBuilder` เท่านั้น ไม่มีการใช้ Stack เพิ่มเติม

---

**การวิเคราะห์เพิ่มเติม**

* ทั้งสองวิธีมีการประมวลผลตัวอักษรทั้งหมด n ตัวเท่ากัน
* การใช้เครื่องหมาย `+` กับ String ทำให้ต้องสร้างอ็อบเจ็กต์ใหม่ทุกครั้ง (เพราะ String เป็น Immutable) ส่งผลให้ช้าลงและใช้หน่วยความจำมาก
* `StringBuilder` เป็นแบบ Mutable จึงสามารถแก้ไขค่าเดิมได้โดยไม่ต้องสร้างใหม่ ทำให้มีประสิทธิภาพสูงกว่า

---

**ผลการทดลองตามขนาดข้อมูล**

* n = 10, 100 → ทั้งสองวิธีทำงานใกล้เคียงกัน
* n = 1,000 → Recursive เริ่มช้ากว่าอย่างเห็นได้ชัด
* n = 10,000 ขึ้นไป → Recursive อาจเกิด StackOverflowError หรือหน่วยความจำไม่พอ
  ขณะที่ Iterative ยังทำงานได้ปกติและรวดเร็ว

---

**เปรียบเทียบข้อดีและข้อจำกัด**

| ประเด็น          | Recursive                               | Iterative                  |
| ---------------- | --------------------------------------- | -------------------------- |
| ข้อดี            | เข้าใจโครงสร้างการทำงานได้ง่าย          | เร็ว และใช้หน่วยความจำน้อย |
| ข้อจำกัด         | ใช้หน่วยความจำมาก เสี่ยง Stack Overflow | โค้ดยาวกว่าเล็กน้อย        |
| Time Complexity  | O(n²)                                   | O(n)                       |
| Space Complexity | O(n²)                                   | O(n)                       |

---

**สรุปผล**
แม้ว่าวิธี Recursive จะอ่านเข้าใจง่ายและเหมาะสำหรับการอธิบายแนวคิด แต่ในทางปฏิบัติจริง วิธี Iterative มีประสิทธิภาพดีกว่าอย่างชัดเจน ทั้งในด้านเวลาและการใช้หน่วยความจำ อีกทั้งยังไม่มีความเสี่ยงจากการเรียกซ้ำลึกเกินไป จึงเหมาะกับการใช้งานกับข้อมูลขนาดใหญ่มากกว่า
